## 三、改动详解

### 1. Claude 模型映射去重（**超高**）

**目的**：清理内置列表中已下线的重复项，并迁移旧选择，避免校验失败回退到默认模型。

- `types.ts:435` `CLAUDE_MODELS` 移除 `claude-fable-5-1`、`claude-opus-5`、`claude-sonnet-5-5`。
- `types.ts:388` `DELISTED_CLAUDE_MODEL_ID_ALIASES` 增加 `claude-fable-5-1 -> claude-fable-5-2`。
- `normalizeClaudeModelId` 匹配顺序不可改：**自定义 id 原样返回** → `LEGACY` → `DELISTED` → 原值。
- `LEGACY`（标记 Retired）与 `DELISTED`（静默迁移）语义不同，**禁止合并**；`isRetiredClaudeModelId` 只认 `LEGACY`。
- 测试：`ModelSelect.test.tsx` 同步期望列表。

**为什么超高**：模型解析在主链路，alias 写错会静默换模型（影响效果与计费）；删列表项必须配 alias，否则旧选择被重置；上游频繁调整模型清单，冲突几乎必现。

**冲突处理**：逐项核对而非整段覆盖，每个删除项必须有迁移目标且目标仍在上游列表；上游新模型一律保留，本 fork 隐藏项只进 `DELISTED`；上游已清理同批型号则改用上游映射。合并后人工验证：旧 id 迁移、自定义 id 不改写、未知 id 原样透传。

### 2. 思考过程自动折叠

**目的**：流式中一旦思考块之后出现正文/工具调用，自动折叠最后一个思考块；用户手动展开的保持展开。

- `MessageItem.tsx:229` 新增 `useEffect`，仅 `isMessageStreaming` 时生效；找最后一个 `thinking` 块，其后有非 `thinking` 块且未在 `manuallyExpandedThinking` 中则折叠。
- 测试：`MessageItem.test.tsx` 的 `thinking auto-collapse` 用例。

**冲突处理**：按「最后思考块 + 其后有内容 + 非手动展开」三条件迁移；上游已有同类逻辑则删除本改动。

### 3. OpenCode 会话展示修复

**目的**：OpenCode 完成后 WebView 快照可能延迟/丢失，实时聊天停在旧内容。修复为在 `stream_end` 先到、CLI 完成时补推一次最终快照。

- `CodexMessageHandler.java:278`：`onComplete` 中增加 `else if (streamEndedBeforeComplete && "opencode".equals(state.getProvider()))`，调用 `notifyMessageUpdate`。仅对 opencode 生效。

**冲突处理**：确认该分支仍在「stream_end 已发生、complete 后到」路径内；上游已修复则删除本分支。

### 4. cc-switch「通用配置」导入

**目的**：cc-switch 的通用配置与供应商配置分层存储，原插件只导入后者，丢失 `env`、`permissions`、Codex 的 `model_reasoning_effort` 等。现在导入时把通用配置作为**底层**合并。

- `read-cc-switch-db.js:219`：从 `settings` 表读 `common_config_claude`/`common_config_codex`，放进 `commonConfig`（旧版无此表则为 `null`）。
- `CcSwitchCommonConfigMerger.java:34`（新增）：Claude 把 JSON 递归垫到 `settingsConfig` 下；Codex 把 TOML 合并进 `configToml`。**供应商值优先**。
- `CodexSettingsManager.java:974`：新增 `mergeCommonConfigToml`/`overlayTomlValues`，并把一批 TOML 工具方法改为 `static`（无逻辑变化）。
- `ProviderManager.java:904,931`：对每个 provider 合并；失败仅 `WARN` 并按未合并导入，不中断整批。
- 测试：`CcSwitchCommonConfigMergerTest.java`。

**冲突处理**：保留「读 `commonConfig` → 逐个合并 → 失败降级」三段语义；优先级不能改成「通用覆盖供应商」。若上游把 TOML 方法改为非 static，优先改调用方，不动上游签名。
